# Workerbee 使用指引（助手知识库）

> **维护责任**：这份文档是基础助手回答「怎么用」的唯一依据，随 UI 迭代同步更新。
> 改了界面文案或操作路径，就要回来改这里——否则助手的回答会腐烂成过时的指引。

## 这个系统是干什么的

Workerbee 是跑在你本机上的多智能体流程编排工具。你在编辑器里画一张流程图：每个节点是一步工作，节点之间的连线表示先后顺序。每个节点配上用哪个 AI 工具（harness，如 Claude Code、Kimi Code）和哪个模型。提交一次任务后，系统按图自动接力执行，前一节点产出的成果交给下一节点，直到全部跑完。

## 日常使用路径

1. 配置 harness 和凭据：到顶栏「注册表」→ Harness 页签点「登记 harness」，填名称和 adapter_id（如 claude_code），保存后点「探测」确认它能用。需要 API Key 的，再到「凭据」页签点「新建凭据」：填名称、API Key，服务地址和默认模型可留空（用官方服务就都不填）。也可以选「用本机登录状态」，不存任何 Key。
2. 画流程：到「流程」页点「新建流程」，创建后自动进入编辑器。点「+ 添加节点」，点选节点在右侧面板配置：名称、执行候选（选 harness、模型、凭据）。在画布上从一个节点拖线到下一个节点表示先后。完成后点「发布」（只点「保存草稿」的话，提交任务时不会用到这版改动）。
3. 提交任务：在编辑器右上或流程列表点「提交任务」，填输入内容（JSON 或纯文本），点提交。被 rejected 时会列出原因，点击可定位到出问题的节点。
4. 看进展：到「任务」页点进任务详情，或到「执行图」页看实时图。失败的任务、等待审批、状态不明的阶段会出现在顶栏「需处理」里。

## 每个页面是干什么的

- 流程（/workflows）：流程的列表。能新建、重命名、删除流程，看每个流程的版本、并发上限和正在运行的任务数。删除流程会终止它正在运行的任务，历史任务记录保留。
- 流程编辑器（点流程名进入）：画和改流程图的地方。左侧画布加节点、连线；右侧面板配节点或翻修订历史。每次保存产生一个新版本，旧版本不会被动过；已在运行的任务仍按各自提交时的版本执行。节点可以停用：停用的节点留在图上可编辑，执行时会被绕过。「校验」按钮检查当前图能不能保存或运行，结论逐条可点击定位。
- 任务（/tasks）：已提交任务的列表，可按状态和流程筛选。失败或受阻的任务会同时标出仍在运行的分支——主链失败不会自动停掉它们。「规则版本」是任务提交时锁定的流程版本。
- 任务详情（点任务进入）：一次任务的全部信息：各阶段状态与失败原因、每次执行尝试用的模型和用量、产物、审批、事件时间线，以及提交时的输入和流程快照。头部有「暂停」「恢复」「删除任务」，作用于整次任务；删除后不能续跑。失败或受阻的阶段行上有「续跑」按钮，只重跑那一个阶段。
- 执行图（/execution）：某个任务实际执行情况的只读图，用的是任务提交时的流程快照，之后改流程不影响它。虚线节点表示状态还在变化中，绿色描边是仍在运行的分支。点节点可看该阶段的尝试、产物和审批，失败的阶段可在这里断点续跑。
- 会话（/sessions）：会话台账，回答「任务连着哪个会话、它还活着吗」。存活（alive）的会话可以点「接入」查看它正在产出什么、必要时发一条消息；接入窗口只显示本次服务运行期间的输出，会话结束后不保留。已失联（lost）表示后台确认会话不存在了，对应阶段会自动重试。
- 注册表（/registry）：四类共享配置。Harness：登记本机的 AI 工具，可探测能力、启停；「支持的功能」矩阵里「未探测」是还没探测过，不是不支持。凭据：密钥加密存在本机凭据库，界面只显示引用；撤销凭据前会列出哪些流程还在引用它，撤销后可以恢复。Skills：写给执行者的指导文本，内容是否被照做取决于执行者，框架不强制。MCP 工具：登记工具的存在、启动方式、风险等级和审批策略（自动放行 / 需审批 / 禁止）。
- 模板（/templates）：把可复用配置存下来。流程模板存整张图，节点模板存单个节点，凭据模板就是注册表里保存的凭据。模板永远不存密钥，只保留凭据引用；同机使用自动绑定，跨机使用时要重新选凭据。「使用模板」创建出来的是草稿，要到编辑器里确认后再保存发布。
- 存储（/storage）：后台服务的运行状态（凭据库是否解锁、调度器有没有启动、部署形态）、数据占用和手动清理。清理默认只预览不删除；去掉「仅预览」后需再确认一次，永久删除不可撤销。未清理的资源会一直列在这里直到被处理。
- 需处理（顶栏按钮）：需要人介入的事：等待审批的请求、失败的任务、状态不明的阶段、没清理干净的资源。点开逐条处置。
- 助手（顶栏按钮）：就是我。回答问题、解释概念、指操作路径；你要求「帮我建一个流程/节点」时，我会给出一张草稿提案卡片——点「采用」才会真正创建（流程只存为草稿，要到编辑器里发布；点「拒绝」则不会创建任何东西）。我不能替你改配置、直接改流程或提交任务。对话变长后只带最近的一段，点「整理前文」可以把较早对话压缩成摘要带上（额外调用一次模型）。

## 概念对照

- 工作流 / 流程（workflow）：你画的那张流程图，任务按什么步骤执行的定义。
- 节点（node）：流程里的一步工作，配有自己的指令、模型候选和工具。
- 任务（task）：向一个流程提交的一次执行。提交时锁定当时的流程版本，之后改流程不影响这次执行。
- 阶段（stage）：任务在某个节点上的那一段执行。
- 尝试（attempt）：阶段的一次实际执行。首次执行、自动重试、换候选各占一条记录。
- 候选（profile）：节点的一组执行配置：harness + 模型 + 凭据 + 运行参数。一个节点可配多组，按顺序尝试，前一组失败才用下一组。
- harness：本机上真正干活的 AI 工具程序（如 Claude Code、Kimi Code），在注册表登记。
- 凭据（credential）：调用模型服务的接入配置（API Key、可选的服务地址和默认模型）。密钥加密存在本机凭据库，别处只存引用。
- Skill：写给执行者的指导文本，运行时随任务注入；框架不保证执行者照做。
- MCP 工具（tool）：登记在册的外部工具。名称和说明会注入给模型；工具进程目前只有 Claude Code 会真正拉起。
- 模板（template）：保存下来复用的配置，分流程模板、节点模板、凭据模板三种，都不含密钥。
- 会话（session）：一次尝试与 harness 之间的运行中连接。任务进展看任务详情，会话页只看连接活没活着。
- 审批（approval）：执行到需要人工确认的操作时停下来等你批准或拒绝，在「需处理」里出现；超时按拒绝处理。
- 产物（artifact）：阶段产出的成果（文本、文件、代码等），带摘要，是交给下游的材料。
- 上游 / 下游：连线的两端。上游先执行，产物交给下游。
- compact（上下文整理）：对话太长时压缩上下文，只保留要点。可在节点候选的高级设置里配阈值。
- supervisor（会话托管）：托管会话的独立进程。顶栏徽标显示「会话托管：独立进程」时，重启后台服务不会打断在跑的任务；显示「后台服务内部」时，重启会打断在跑的任务。
- 断点恢复（checkpoint）：暂停或中断时保留的现场，续跑时从断点接着跑；没有断点就从本阶段头重跑。
- 修订（revision）：流程的每次保存产生一个新版本号，旧版本不可变。
- 钉扎快照（pinned snapshot）：任务提交时锁定的流程版本，本次执行、历史回看、恢复都以它为准。

## 常见状态与报错是什么意思

任务状态：
- 排队中：已提交，等待调度。若一直不动，去「存储」页看调度器是不是没启动。
- 运行中：正常执行。
- 暂停中 → 已暂停：你点了暂停，正在或已经停下。已暂停可点「恢复」继续；已完成阶段的结果保留，不重跑。
- 取消中 → 已删除：你点了删除，不可恢复；历史记录仍可查看。
- 已成功 / 已失败：终态。失败的任务进「需处理」，详情页同时给出失败原因和仍在运行的分支。
- 受阻：依赖未满足或输入不够，详情页有具体原因；处理后可续跑。
- 核对中：系统在确认任务的真实状态，暂时无法确定它还在不在跑，等核对结束或人工核对。

阶段状态：
- 等待依赖：上游还没完成。就绪排队：上游好了，等空闲执行位。分派中：正在创建会话。
- 运行中：正常执行。
- 等待审批：有个操作等你处置，去「需处理」批准或拒绝。等待期间不占执行位。
- 退避重试中：出了可重试的错（网络、限流等），等一会儿自动重试，不用管。
- 已失败：这个阶段的所有候选都失败了。点「续跑」重跑该阶段（有断点从断点续，没有从头跑）。
- 已跳过：节点被停用，这次执行绕过了它。
- 受阻：上游失败、上游被删，或交接的材料不够。看原因再决定续跑还是改流程。
- 状态不明（lost）：系统确认不了它的真实状态（比如服务崩溃过）。需要人工核对：去会话页看会话是否失联，确认后决定续跑还是放弃。

常见报错：
- 凭据库未解锁：内核启动时没带口令，读不到任何密钥，引用凭据的阶段会在执行时报错。处理：用带口令的方式重启内核（--passphrase 参数或 WORKERBEE_PASSPHRASE 环境变量）。
- 凭据已撤销：引用的凭据被撤销了。到「注册表 → 凭据」恢复它，或在节点候选上改选别的凭据。
- 建立会话失败 / 超时：没能拉起 harness。检查注册表里该 harness 的探测结果、可执行路径和认证配置；属于可重试错误时系统会自动重试。
- 交接失败：上游产物的摘要没覆盖下游要求的内容，下游被挡住，直到材料补齐。这不代表任务失败。去任务详情看受阻阶段和标红的产物；要么续跑上游阶段补齐内容，要么回编辑器调整下游的「要求上游提供的内容」或连线契约。
- 契约校验失败：阶段产出没满足连线上声明的输出要求。这类错误不会自动重试，会换下一组候选或直接失败；改节点的产出要求或上游节点的指令。
- 上下文组装失败：准备发给模型的材料时出错。常见原因是上游产物缺失（伴随交接失败）；可重试的会自动重试，持续失败看事件时间线里的具体原因。

## 常见问题

- 凭据怎么配：到「注册表 → 凭据 → 新建凭据」。API Key 必填（除非选本机登录态）；服务地址只有走第三方网关或自建服务时才填；默认模型可留空，节点候选里填的模型名优先，节点留空才用凭据的默认模型，凭据也没有就用 harness 登录态的默认模型。一份「地址 + Key + 默认模型」的凭据就是一套完整接入配置，各节点直接引用。
- kimi 和 claude 有什么差别：kimi 靠本机登录态认证（先跑过 kimi login），不用配 Key。MCP 工具：只有 claude 会真正拉起工具进程，kimi 只注入工具的名称和说明。Skills：给 kimi 节点引用 Skill 时，会作为会话级技能目录传给 kimi，顶替 kimi 自动发现的技能目录——引用前先想清楚。
- 任务失败了去哪看原因：任务详情页的「运行总览」同时列出失败原因、失败的阶段和仍在运行的分支；再往下翻执行尝试（每次尝试的模型、用量、错误细节）和事件时间线（可按类型过滤）。「需处理」抽屉里也能直接点进失败任务。
- 助手（我）怎么配：点顶栏「助手」→「设置」：打开「启用助手」，选一条模型凭据。凭据必须含 Base URL 和 Key——本机登录态类型的凭据不能给助手用。模型名留空则用凭据的默认模型。凭据库未解锁时发问会失败，历史消息仍可翻看，带口令重启内核后恢复。
